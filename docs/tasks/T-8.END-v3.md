## Chẩn đoán & 2 sửa (YÊU CẦU CHÍNH)

### Lỗi 1: State cũ rem-at (Scenario 2)
**Nguyên nhân:**
- ReminderDialog giữ state `at` giữa các lần mở dialog
- useEffect([open]) đặt lại mặc định SAU render
- `not.toHaveValue('')` qua ngay với giá trị CŨ
- Sau đó effect ghi đè → fill bị mất

**Cách sửa:**
Dùng helper `setRemAt()` với poll/retry:

```typescript
async function setRemAt(page: Page, value: string) {
  await expect(async () => {
    await page.getByTestId('rem-at').fill(value);
    await page.waitForTimeout(150);  // đợi effect chạy + ghi đè
    await expect(page.getByTestId('rem-at')).toHaveValue(value, { timeout: 100 });
  }).toPass({ timeout: 5000 });  // retry fill tới khi giá trị đứng yên
}
```

**Áp dụng:**
Thay tất cả `await page.getByTestId('rem-at').fill(...)` bằng `await setRemAt(page, '...')`.

Danh sách (từ v2):
- Scenario 2: L127 `'2026-10-05T23:59'`
- Scenario 3: L139 `'2026-10-06T00:10'`, L145 `'2026-10-06T00:30'`
- Scenario 4: L154 `'2026-10-08T10:00'`, L159 `'2026-10-05T09:00'`
- Scenario 5: L187 `'2026-10-06T08:00'`

### Lỗi 2: __lastNav cũ (Scenario 5 + 1, 7)
**Nguyên nhân:**
- Test đọc `window.__lastNav` CŨ (từ bấm trước)
- Trước khi bấm lưu giá trị cũ, sau bấm kiểm không thay đổi

**Cách sửa:**
Khi bấm nút dẫn tới Shortcut, thêm:

```typescript
// Trước bấm: lưu __lastNav hiện tại
const oldNav = await page.evaluate(() => (window as any).__lastNav);

// Bấm nút
await page.getByTestId('rem-dayalarm').click();

// Sau bấm: chờ __lastNav thay đổi (không phải cũ)
await expect.poll(() => page.evaluate(() => (window as any).__lastNav), { timeout: 5000 })
  .not.toBe(oldNav);

// Rồi mới lấy + giải mã
const newNav = await getLastNav(page);
expect(newNav).toBeDefined();
const payload = extractDecodedPayload(newNav!);
```

- Scenario 5 (L191 sau bấm rem-dayalarm)
